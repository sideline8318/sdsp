## 1. 目标

交付一个可访问的俄罗斯方块 Web 小游戏，用户可以打开线上地址并完成核心玩法（移动、旋转、消行、计分、结束与重开），同时发布地址与版本可回读。

## 2. 需求条目（EARS）

- R-EARS-01：系统应提供一个单入口的 Web 页面，通过一个 HTTPS 地址访问。
- R-EARS-02：系统应为纯静态实现，运行时不依赖后端服务与网络请求。
- R-EARS-03：页面应在主流桌面浏览器（Chrome/Edge/Firefox 最新版）正常渲染与运行。
- R-EARS-04：系统应渲染一个 10 列 × 20 行的游戏棋盘。
- R-EARS-05：系统应支持 I、O、T、S、Z、J、L 共 7 种方块。
- R-EARS-06：当游戏运行时，系统应按固定节奏使活动方块自动下落一格。
- R-EARS-07：当用户按下左/右键且目标位置无碰撞时，系统应将活动方块水平移动一格。
- R-EARS-08：当用户按下旋转键且旋转后位置无碰撞时，系统应旋转活动方块。
- R-EARS-09：当用户按下软降键时，系统应使活动方块加速下落一格并相应计分。
- R-EARS-10：当用户按下硬降键时，系统应使活动方块立即落到底部并锁定。
- R-EARS-11：当旋转后位置发生碰撞时，系统应拒绝旋转并保持方块原状。
- R-EARS-12：当一行被填满时，系统应消除该行并使上方内容下移。
- R-EARS-13：当方块锁定或消行时，系统应更新分数、消除行数与等级。
- R-EARS-14：系统应预览下一个方块。
- R-EARS-15：当新方块出生位置即发生碰撞时，系统应进入游戏结束状态并展示提示。
- R-EARS-16：当用户触发重新开始时，系统应将棋盘、分数、行数与等级复位到初始状态。
- R-EARS-17：当用户访问发布地址时，系统应返回可正常加载的页面且无阻断性错误。
- R-EARS-18：系统应在页面上展示版本号，并可通过 `version.json` 与 `window.__APP_VERSION__` 回读。
- R-EARS-19：发布地址与版本号应可被记录并在验收阶段回读。

## 3. 非功能需求

- NFR-1 性能：游戏循环稳定，主循环使用 `requestAnimationFrame`，避免每帧全量 DOM 操作。
- NFR-2 兼容性：仅使用标准 ES2020+、Canvas 2D、`requestAnimationFrame`。
- NFR-3 可维护性：模块单一职责、命名语义化、逻辑层与渲染层解耦。
- NFR-4 可复现性：提供固定的开发/构建命令，README 记录端口与回退方式。
- NFR-5 合规：不引入后端、不建立隧道、不进行扫描或攻击行为。

## 4. 范围外

- 触屏/移动端手势操作（默认范围外，桌面键盘为核心路径）。
- 多人对战、排行榜、账号体系。
- 音频与高级粒子特效。

## 5. 验收标准

- AC-001：七阶段流程完成，生产页面可访问，核心俄罗斯方块玩法可用，发布地址和版本可回读。
